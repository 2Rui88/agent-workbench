# 项目协作者只读可见与下游验证设计

## 目标

项目创建人可以通过分享码或邀请链接邀请其他 owner 加入项目。加入后的协作者可以查看项目内全部任务，但只能操作自己 owner 的任务；跨 owner 只保留现有的下游依赖验证流程。

## 权限边界

| 角色 | 项目/任务可见性 | 自己任务操作 | 他人任务操作 | 项目成员管理 | 跨 owner 下游验证 |
| --- | --- | --- | --- | --- | --- |
| 项目创建人 | 项目内全部 | 允许 | 禁止 | 允许 | 按验证流程允许 |
| 项目协作者 | 项目内全部 | 允许 | 禁止 | 禁止 | 按验证流程允许 |
| 未授权 owner | 不可见 | 不适用 | 不适用 | 不允许 | 不允许 |

“项目创建人”只表示项目归属，不授予修改其他 owner 任务的管理员权限。任务执行人仍由任务自身的 `owner` 决定，创建人 badge 与任务执行人 badge 保持分离。

## 分享与加入

1. 创建人从项目页生成分享码/邀请链接。分享凭证包含项目 ID 和随机 token，数据库只保存 token 哈希。
2. 分享凭证默认短期有效、单次消费；创建人可在项目成员页撤销尚未消费的凭证，也可移除已加入成员。
3. 被邀请者使用自己已认证的 Board/MCP owner 接受邀请，服务端以认证 owner 写入成员关系，不接受请求体中的任意 owner。
4. 项目名只用于展示和辅助搜索，不能作为授权凭证；项目 ID 在未授权时也不能用来读取项目或任务。

## 可见性与操作

- 全局总览继续显示系统允许展示的项目和任务；项目成员在个人项目列表中看到自己创建或加入的项目。
- 成员读取项目、仓库、任务详情和任务列表时，返回项目内全部任务，但不改变任务的实际 owner。
- 创建任务时执行人固定为当前认证 owner，不能通过参数替换成其他 owner。
- 任务修改、认领/释放 session、开始、暂停、验收和取消等普通写操作，只允许任务 owner 执行；项目创建人不能越权操作协作者任务。
- 跨 owner 的依赖验证沿用现有 validation contract：下游 owner 可以读取、接收、推进和完成自己的验证请求；验证动作只更新验证记录和下游门禁，不修改上游任务状态或内容。
- 被移除成员立即失去项目读取和写入权限，历史任务和审计记录保留。

## 数据模型

新增项目成员表，至少包含：

- `project_id`
- `owner`
- `role`（当前固定为 `member`，创建人由 `projects.created_by` 表示）
- `granted_by`
- `created_at`
- `revoked_at`

新增分享凭证表，至少包含：

- `share_id`
- `project_id`
- `token_hash`
- `created_by`
- `expires_at`
- `consumed_at`
- `revoked_at`
- `created_at`

对 `(project_id, owner)` 保证未撤销成员关系唯一；对 token hash 保证单次消费和不可逆存储。历史 `created_by IS NULL` 项目不自动推断创建人，也不自动生成成员关系；需要时由已知 owner 显式创建分享。

## 接口与错误

- `POST /api/projects/:projectId/shares`：创建人生成分享凭证。
- `DELETE /api/projects/:projectId/shares/:shareId`：创建人撤销未消费凭证。
- `POST /api/project-invitations/:token/accept`：当前认证 owner 接受邀请并加入项目。
- `DELETE /api/projects/:projectId/members/:owner`：创建人移除成员。
- 项目/仓库/任务读取接口统一检查成员关系；个人项目接口将成员项目加入结果。
- 普通任务写接口在 owner 校验前增加项目成员校验，分别返回 `PROJECT_ACCESS_REQUIRED`、`PROJECT_MEMBER_REVOKED` 或 `TASK_OWNER_MISMATCH`。
- 下游验证接口只允许验证请求对应的下游 owner，并继续使用验证请求的状态机和审计记录。

Board 和 MCP 都使用服务端已认证的 owner；不得允许调用方通过 `owner`、`created_by` 或查询参数绕过成员校验。

## 前端行为

- 项目卡片保留“项目创建人” badge，并增加“分享项目/成员管理”入口（仅创建人显示）。
- 成员项目出现在个人列表；项目内他人任务显示为只读，隐藏或禁用普通操作按钮，并给出只读原因。
- 跨 owner 验证入口只在存在可验证的下游验证请求时显示。
- 分享成功、加入成功、撤销和权限拒绝均显示明确反馈；项目名、项目 ID 和 token 不在日志中明文输出。

## 验收标准

1. 创建人生成的分享凭证可被另一 owner 接受，成员关系持久化且可撤销。
2. 成员个人列表可见该项目及项目内全部任务；未授权 owner 不能通过项目名、项目 ID 或仓库切换器发现它。
3. 成员只能操作自己 owner 的任务；对其他 owner 的普通操作稳定返回权限错误。
4. 跨 owner 下游验证可正常完成，且不能修改上游任务。
5. 历史无 creator 项目仍显示“未分配”，不被自动归属或自动公开。
6. SQLite 迁移、Board/MCP/API、前端和实时刷新均有自动化测试，并通过 Edge 实际验证。
