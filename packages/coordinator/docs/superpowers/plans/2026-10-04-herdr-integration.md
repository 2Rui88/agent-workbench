# Herdr 动态角色布局实施计划

已由用户确认执行：Kitty 承载 Herdr，当前主会话在 Herdr 内恢复，角色按实际任务激活出现。

影响范围：`src/terminal/*`（受控 Socket、布局、状态投影）、`scripts/herdr-*`（观察控制与恢复入口）、`src/engine.ts`（安全事件元数据）、`package.json`、终端测试及本项目验证说明。其他项目及全局配置不修改。

约束：主窗格不替换、不关闭；只操作自身创建的窗格；显式 pane/tab/socket，缺失即停止；不依赖 UI 焦点；后台 App Server 仍由协调器执行，观察窗格不重复启动模型；布局命令结果不明时停止，不盲目重试；用户窗格新增后不重排它；完成结果默认保留，显式 compact 才收起；保留 unknown/blocked/人工请求。主会话在 Herdr 外不得控制默认会话。

- [x] 测试先行验证初始化无窗格、1→3→4、短暂空闲保持、焦点不变、外来窗格保护、失败不重复创建。
- [x] 实现 Socket 客户端、幂等控制器与均衡布局，保存映射、ready/pending 和单实例锁。
- [x] 接入 SQLite 只读投影及有界安全事件元数据，显示模型/思考/队列/阻塞/线程/turn。
- [x] 实现必须在明确 Herdr 主窗格执行的恢复入口，恢复指定会话 UUID。
- [x] 隔离 Herdr 实例真实协议验证；完整测试、类型及构建；提供人工启动命令。

验收范围：布局适配和恢复入口可运行，不将其描述为 App Server 独立写租约或真实模型审计已完成。

验证决策：安装版协议实测表明 `layout.apply` 重建 tab/PTYS，禁止用于动态接入；改用 `pane.split`（right/down/down）保持进程与 ID。元数据使用 Herdr 允许的 working/idle/blocked 标签，不冒充交互 Agent 生命周期。

强模型只读审查指出 pending 启动状态、compact 进程身份与后台监督三项问题，均已修复；未新增模型开发或自动重试。事件日志每角色只保留 200 条生命周期元数据，不保存原始模型文本、工具参数或命令输出。
